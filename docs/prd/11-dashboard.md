> Dashboard 不是统计报表，而是 **Project Intelligence**：
> 它不只告诉你"发生了什么"，还要回答"为什么"和"接下来该做什么"。

## 1. 四个视角

### 1.1 Project

| 指标 | 定义 | 数据来源 |
| --- | --- | --- |
| Burn Down | 剩余工作量随时间变化 | Task/Story 事件流 |
| Velocity | 每迭代完成点数（近 6 迭代趋势） | Sprint 完成事件 |
| Milestone | 里程碑达成率与预测偏差 | Milestone + 进度预测 |
| Risk | 风险数量、等级分布、逾期未缓解数 | Risk 对象 |
| Budget | 预算 vs 实际（人力 / Token / 云成本） | Budget + 成本归因 |
| Scope Change | 需求变更次数与影响范围 | RequirementChanged 事件 |
| Cycle Time | Story 从 Approved 到 Done 的时长分布 | 状态迁移事件 |
| Lead Time | 从提出到发布的端到端时长 | 全链路事件 |

### 1.2 Team

| 指标 | 定义 |
| --- | --- |
| Capacity | 可用工时/点数 |
| Workload | 实际负载与分布均衡度（含单点风险） |
| Review Time | PR/设计评审的等待与处理时长 |
| WIP | 在制品数量与是否超限 |
| Blocked Time | 任务处于 Blocked 的累计时长 |
| Human vs Agent | 人与 Agent 的工作量占比 |

### 1.3 Agent

| 指标 | 定义 |
| --- | --- |
| Cost | 按 Agent / Project / Requirement 归因的成本 |
| Token | Token 消耗趋势与分布 |
| Success Rate | Run 成功率（成功 / 总 Run） |
| **Automation Rate** | 由 Agent 独立完成且被接受的工作项占比（**北极星指标**，口径见 §2） |
| Acceptance Rate | Agent 产出的人工采纳率 |
| Rework Rate | 采纳后 7 天内被推翻的比例 |
| Latency | Run 时延 P50 / P95 |
| Ask Rate | 触发人工确认的比例（过高说明权限或护栏设置需调整） |

### 1.4 Knowledge

| 指标 | 定义 |
| --- | --- |
| New Knowledge | 新增知识对象数量 |
| Reuse Rate | 被引用/复用的知识占比 |
| Decision Coverage | 重大变更中有 ADR 记录的比例 |
| Staleness | 过期未复核的知识占比 |
| Orphan Rate | 无关系连接的孤儿对象占比（本体健康度） |
| Traceability | Requirement → Release 全链路可追溯覆盖率 |

## 2. Automation Rate 口径（北极星指标定义）

北极星指标必须有唯一、可争议性最小的口径，否则无法验收。

### 2.1 自动化分级

每个进入终态的工作项，按**人工介入程度**归入四级：

| 级别 | 定义 | 判定依据 |
| --- | --- | --- |
| **L0 人工** | 产出完全由人生成 | 无关联 AgentRun |
| **L1 AI 辅助** | Agent 出草稿，人工大幅修改 | 采纳前人工编辑幅度 **> 20%** |
| **L2 AI 主导** | Agent 出稿，人工小幅修订 | 编辑幅度 **≤ 20%** 且 > 0 |
| **L3 AI 独立** | Agent 产出被原样接受 | 编辑幅度 **= 0** |

**编辑幅度**定义：从 Agent 产出（Artifact 首个版本）到进入终态时的最终版本之间，
按结构化字段计算的变更比例——文本字段用字符级 Levenshtein 距离占比，
结构化字段用「变更字段数 / 总字段数」，多字段对象取加权平均。

### 2.2 公式

```
Automation Rate = L3 工作项数 / 同期进入终态的全部工作项数
AI 主导率        = (L2 + L3) / 同期进入终态的全部工作项数
```

**分子（L3）必须同时满足**：

1. 该工作项的最终产出关联到某个 `AgentRun` 的 `Artifact`
2. 采纳前的人工编辑幅度 = 0
3. 产出被接受并进入终态（`Done` / `Approved` / `Merged` / `Published`）
4. 采纳后 **7 天内未被推翻**（未 reopen、未回滚、未被 supersede、未产生指向它的 P0/P1 缺陷）

**分母**：同期进入终态的全部工作项，人做的与 Agent 做的都算。

### 2.3 不计入的行为

| 行为 | 为什么不计入 |
| --- | --- |
| Workflow 自动化规则（状态推进、字段赋值、通知） | 是流程自动化，不是 AI 承担工作 |
| Dashboard 指标物化、关系自动建立 | 系统内建能力，非交付工作 |
| Agent 的只读操作（检索、推荐、问答） | 未产生可交付物 |
| 被拒绝或未进入终态的 Agent 产出 | 未产生实际价值 |

### 2.4 计入的对象类型

`Requirement` / `Story` / `Task` / `Issue` / `PR` / `Decision` / `Knowledge` / `Meeting` / `TestCase`
（可按项目配置子集；配置变更需重算历史值，避免口径漂移造成指标跳变）

### 2.5 消歧规则

| 情况 | 判定 |
| --- | --- |
| 人工点击"接受"但未修改内容 | **算 L3**——点击接受是审阅行为，不是编辑 |
| 触发了 Ask 人工确认但未修改内容 | **算 L3**——确认是授权行为，不是编辑 |
| 多个 Agent 接力完成 | 算一次 L3，归因到最后产出 Artifact 的 Agent |
| 人先写草稿、Agent 补全 | 按最终编辑幅度判级，不因"人先动手"降级 |
| 7 天内被推翻 | 从 L3 移除并回溯修正历史值，同时计入 Rework Rate |

> **口径变更必须走 ADR**，并对历史数据重算，Dashboard 上标注口径版本。

## 3. 从"统计"到"智能"

Dashboard 的每个异常指标都必须可**下钻到证据实体**，并给出可执行建议。

```
Velocity 下降 22%
   │  ▼ 下钻
   ├─ 归因：Blocked Time 增长 3.1×
   │    └─ 主要阻塞源：Task:441（等待 API 契约确认）
   │         └─ 关联：Architecture 变更 ARCH-88 无 ADR
   └─ 建议：
        · 为 ARCH-88 补充 Decision（一键调用 Architecture Agent 起草）
        · 将 Task:441 升级为阻塞项并指派 owner
```

规则：

| # | 规则 |
| --- | --- |
| I1 | 每个指标可下钻至构成它的实体清单 |
| I2 | 异常检测基于历史基线，而非固定阈值 |
| I3 | 归因结论必须沿本体关系给出路径，不做无依据推测 |
| I4 | 建议必须可一键执行（创建 Task / 调用 Agent / 发起审批） |
| I5 | 指标由事件流物化，**不存在人工填报** |

## 4. 实现要求

| 项 | 要求 |
| --- | --- |
| 计算方式 | 事件驱动增量物化视图；重算可回放事件重建 |
| 新鲜度 | 核心指标延迟 ≤ 1 分钟；成本类 ≤ 5 分钟 |
| 权限 | 指标遵守资源级权限：用户看不到无权访问对象贡献的明细（聚合值可按策略脱敏或隐藏） |
| 时区 | 按 Workspace 配置，跨时区团队一致 |
| 导出 | 支持 CSV / API 导出；支持订阅定期推送 |
| 自定义 | 支持自定义看板与指标组合（v1.1） |
