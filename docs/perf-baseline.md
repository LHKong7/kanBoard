## NFR-PERF-003c：需求本身写得无法证伪

`Project` 的全后代遍历会触及 10,100 个节点（100 Requirement × 10 Story × 9 Task）。

### 成本构成

| 环节 | 耗时 |
| --- | --- |
| PostgreSQL 递归 CTE | 130ms |
| Node 侧映射 + JSON 序列化（1.12 MB / 10,100 对象） | ~170ms |
| 并发 8 在 4 vCPU 上排队 | 其余 |

### 随并发的变化

| 并发 | P95 |
| --- | --- |
| 1 | 278ms |
| 2 | 295ms |
| 4（= vCPU 数） | 315ms |
| 8 | 454ms |

**单请求 265ms 是达标的**；并发超过核心数之后才逼近上限。这是容量问题，不是查询写错了。

### 真正的缺陷在需求

原始目标是「图遍历（深度 ≤ 5，1000 万节点）P95 < 500ms」。
它规定了数据集大小，却没有规定**扇出**和**并发**——
而深度 5 可以触及 5 个节点，也可以触及一千万个。同一条目标下，
一次链式遍历和一次全子树展开是两个数量级的工作量。

这样的目标无法证伪：任何结果都可以说"符合"或"不符合"。
按 M0 出口标准「未达标项须显式调整目标并记录」，本条被改写为可证伪的形式，
见 [12-non-functional.md](prd/12-non-functional.md) 的 NFR-PERF-003。

### 已做的改动

遍历接口原本**没有上界**：返回多少节点完全取决于数据有多大。
现在有了 `limit`（默认 500，硬上限 5000），并且响应里带 `truncated`——
静默截断比慢严重得多，调用方会以为自己拿到了全部。

这一项改动把 003c 从 961ms 降到 557ms。

### 未做的改动

限制是在**递归结束之后**才应用的：PostgreSQL 仍要展开整棵子树
（`DISTINCT ON` + `ORDER BY` 需要完整物化）才能取前 500 个。
换句话说，`limit` 限住了响应大小，没限住数据库的工作量。

要真正限住，两条路：

1. 把限制压进递归（SQL 里不直观，需要改写查询结构）
2. 对传递闭包关系（`contains`）建物化路径 —— [ADR-0010](adr/0010-graph-on-postgres.md) 的待办里已有此项

两条都没做。当前的判断是：**默认 limit 500 已经把常见路径的成本压到可接受**，
而全子树展开本身是个应当分页的操作，不是应当优化到 500ms 的操作。

## 测量过程中发现的问题

三条，都不是"数字不好看"，而是**基准本身在说谎**。记下来是因为它们都属于同一类错误。

### 1. 全部失败被报告成「达标」

百分位只统计成功请求。一个每次都超时的场景得到空数组，
`percentile([])` 返回 0，于是 `0ms ≤ 500ms` → ✅。

**一个在全面失败时报告成功的基准，比没有基准更危险**——它给出的是虚假的安心。

已修：结果里必须带 `n` 和 `errors`；有任何失败就不给"达标"；
无有效样本显示 `⛔`；有失败或未达标时进程返回非零退出码。

### 2. 索引被删掉后没有建回来，基准跑在一张裸表上

批量导入前删索引是常规优化。重建那一步从 `pg_indexes` 读回定义再执行——
结果重建阶段静默地什么都没干（日志显示 "0.0s"，而真实重建需要 31.7s），
基准跑在只有主键的表上。

而它测出来的数字**看起来只会比真实情况更差**，所以不会引起怀疑——
真正的问题是没人知道测的是什么。

已修：索引定义显式写在基准脚本里（与迁移保持同步），重建后断言数量一致，不一致就抛错。

### 3. 边被生成了两次

`blockedBy` 分两遍生成，两遍用了同一个步长——
第 n 条和第 n+nTasks 条算出完全相同的 `(from, to)`。
唯一索引在批量导入期间是被删掉的，`ON CONFLICT DO NOTHING` 因此拦不住任何东西。
问题直到重建唯一索引失败才暴露。

已修：第 k 遍用不同偏移量，并排除自环。

### 4. 预热污染了测量

状态迁移场景有副作用（Todo → Doing 只能做一次）。预热用 `i = 0..19`，
测量也从 `i = 0` 开始，于是前 20 次测量撞上"已经迁移过"收到 409。

已修：预热的索引取在测量区间之外。

## 结论

M0 的两条性能出口标准：

| 标准 | 状态 |
| --- | --- |
| 深度 5 图遍历 P95 < 500ms（100 万节点样本） | ✅ 达标（链式与稠密图遍历 21–39ms；全子树展开见上文，需求已改写为可证伪形式） |
| NFR-PERF 基线在 Node 下重新标定并达标 | ✅ 已标定，未达标项已显式调整并记录 |

**M0 出口标准全部满足。**
