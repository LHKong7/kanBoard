## Workflow 细分

这一行之前记的是 **7/9，缺「SLA 超时、可视化编辑器」**。那两项分别是
FR-WF-013（S）与 FR-WF-014（C），**根本不是 Must**——
也就是说这份表把缺口指错了地方，而真正缺的两条一直没被记下来。
逐条核对之后的实际情况：

| ID | 状态 |
| --- | --- |
| FR-WF-001 可配置状态机，改完即时生效 | ✅ 定义存库 + TTL 热加载 |
| FR-WF-002 guard / capability / actions / SLA | ✅ SLA 巡检会真的告警与升级；此前它只是个没人读的字段 |
| FR-WF-003 非法迁移返回可读原因 | ✅ 三种失败分开报 |
| FR-WF-004 迁移经 PDP 授权 | ✅ |
| FR-WF-005 when/if/then，8 类动作全部可用 | ✅ 8 类齐了（此前只有 3 类） |
| FR-WF-006 外部事件触发（GitHub / CI / Kafka） | ❌ 需要真实外部系统，见连接器一节 |
| FR-WF-007 invokeAgent 动作 | ✅ 创建 AgentRun，与人发起的走同一条路径 |
| FR-WF-008 触发链深度与频率限制 | ✅ 环形规则被熔断并留痕 |
| FR-WF-009 自动化执行全量留痕 | ✅ 含条件求值明细与"没动的原因" |

`sla` 曾经是这份表里最典型的一处虚报：它在状态定义里、在类型里、
在 Task 的 `Doing` 上都写着，**但没有任何代码读它**——
一个看起来配置好了、实际什么也不做的字段，比没有这个字段更糟，
因为有人会以为超时会有人管。现在它由 `SlaSweeper` 巡检，
超时会生成通知或升级到值班，每一条都种过缺陷验证会红。

计时用单独的 `status_since` 列而不是 `updated_at`：后者被任何一次编辑刷新，
于是一个停滞三周、昨天被人补了个描述的任务看起来"刚动过"——
而那正好是最该报警的对象。

FR-WF-006（外部事件触发）是这一模块唯一还缺的 Must，它需要真实的
GitHub / CI / Kafka，和连接器一节里的四个集成是同一个阻塞。

「指标即查询」的代价要说清楚：现算在百万行规模上没问题
（[性能基线](perf-baseline.md)里列表查询 P95 约 20ms），
再大一个量级就需要物化。届时这份指标定义就是物化任务的输入，
不需要重写口径。

**Automation Rate 是唯一的例外，它明显更贵**：每个工作项都要拉一次历史
再算一次编辑距离，是一次 N+1。目前用一条 5,000 项的硬上界兜住，
命中时响应里的 `truncated` 为 true——**少算可以，不声不响地少算不行**。
这一条是已知的、要还的债，不是"没想到"。

## 差得最远的两块

**AI 能力（12 Must，交付 1）。** Agent Runtime 的骨架在了——身份、上下文出处、
预算熔断、协作模式、Run 轨迹都能跑——但具体能力（自动拆 WBS、估点、
识别风险、写 PRD）一个都没做。这些需要真实模型，而当前只有确定性实现。
**没有凭据时 runner 默认不启动**，因为退回到假实现会安静地产出一堆
无意义的草稿，而草稿是会被人当真的。

**连接器（12 Must，交付 8）。** 统一契约与网关做完了——授权、审计、幂等、
限流、退避重试、熔断、白名单、人工确认、凭据注入、按分级脱敏，
全部在**唯一入口**上强制执行，每一条都种过缺陷验证会红。
FR-CON-002「无法绕过」用两条 CI 规则挡住（依赖分析 + 源码扫 `fetch`），
两条都验证过会触发。

缺的是具体集成：GitHub（006）、Jira（007）、MCP（008）、Browser（009/010 的实际浏览器）。
它们需要真实的外部系统与凭据，在当前环境里做不出可验证的东西——
写一个连不上任何东西的适配器，只会得到一个看起来完成的空壳。
契约已经把它们变成薄薄一层：实现 `Connector` 接口，声明操作与白名单即可，
所有的保证由网关提供。
