# ADR-0012：重开是一条显式的边，不是终态的例外

| 项 | 值 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-04 |
| 相关 | FR-WF-002、FR-DASH-016、[ADR-0011](0011-dogfooding-first.md) |

## 背景

工作流引擎有一条注册期校验：**终态不允许有出边**。

```
lifecycle "task-default": state "Done" is marked terminal
but has an outgoing transition to "Doing"
```

写这条规则的理由是好的——一台把 `Done` 又连回去的状态机，
说明 `Done` 根本不是终态，而这种自相矛盾最好在注册时就炸掉，
而不是等到有人问"为什么已完成的任务数一直在跳"。

问题在实现 FR-DASH-016 时出现：北极星指标的口径（PRD §2.2 第 4 条）
要求 L3 满足「采纳后 7 天内未被推翻（未 reopen、未回滚、未被 supersede…）」。
PRD 点名了 reopen。而按现有规则，**系统里根本不存在 reopen 这条边**——
Task 的 `Done`、Story 的 `Done`、Requirement 的 `Finished` 都是死路。

于是出现一个很难看的局面：北极星指标要扣除的那件事，
在这个系统里不可能发生。指标会永远显示 Rework Rate = 0，
不是因为质量好，是因为无法表达。

这不是"指标写错了"。真实项目里任务天天被重开。
**一个不能表达返工的项目系统，测出来的自动化率必然虚高。**

## 决策

区分两件被混在一起的事：

- **终态（terminal）**：这个状态算"完成"。指标据此计入分母，SLA 停止计时。
- **封闭（没有出边）**：不能再走到别处。

原规则把两者当成同一件事。改成：**终态默认没有出边，
但可以有显式标注 `reopen: true` 的出边。**

```ts
{ from: ['Done'], to: 'Doing', reopen: true, capability: 'Task.Execute' }
```

注册期校验相应改成三条：

1. 终态的出边**必须**标 `reopen`——不标就还是报错，
   原来那条"把 Done 悄悄连回去"的错误照样拦得住。
2. 标了 `reopen` 的边**必须**从终态出发。
   否则这个标记会变成一个可以随便贴的装饰，
   而 FR-DASH-016 正要靠它判断"这是一次推翻"。
3. `reopen` 的目标**不能**是终态。终态之间横跳不是重开，
   是分类错误（要表达"完成后被取消"，该用 supersede 关系而不是迁移）。

## 后果

**指标口径变得可判定。** 「被推翻」不再需要靠"离开了终态"去猜——
它就是走过一条 `reopen` 边。FR-DASH-016 的 Rework Rate 有了明确来源。

**重开是一件被看见的事。** 它有自己的迁移记录、自己的 Capability
（Task 用 `Task.Execute`，Requirement 用 `Requirement.Approve`——
谁有权批准，谁才有权推翻），因此会进审计日志。
在此之前，"这个需求其实返工过三次"这件事在系统里没有任何痕迹。

**代价：终态不再等于封闭。** 任何读到 `terminal: true` 就假设
"不会再变"的代码都可能出错。目前有两处依赖这个假设：
指标的分母计算（已按"进入过终态"重写）与 SLA 计时（重开后重新计时，
这正是期望行为）。这条代价写在这里，是为了下一个人加第三处时能看到。

**没有为 Decision 和 Knowledge 开重开边。** 已被取代的决策不该被"重开"——
ADR 的规矩是写一条新的去取代它（见 `docs/adr/README.md`），
归档的知识同理。能重开不等于都该重开。
